# La Storia — сайт пиццерии с админкой

Готовый к работе сайт пиццерии для рынка Молдовы: публичный каталог с
корзиной и оформлением заказа **на 4 языках** (румынский, русский,
английский, итальянский) в стиле винтажного итальянского постера + закрытая
админ-панель на русском для управления каталогом, переводами, доставкой,
промо, заказами и аналитикой.

Этот README написан в двух частях:

1. **[Запуск на своём компьютере](#запуск-на-своём-компьютере-для-разработчика)** — для разработчика, который дорабатывает код.
2. **[Запуск сайта на сервере через aaPanel](#запуск-сайта-на-сервере-через-aapanel)** — пошаговая инструкция для владельца сайта без опыта в IT, максимально через кнопки веб-панели, с минимумом набора команд в консоли.

Если вы просто хотите разместить сайт в интернете — переходите сразу ко
второй части.

## Стек

- **Next.js 16 (App Router)** + TypeScript (strict)
- **next-intl 4** — 4 языка сайта: `ro` (основной, без префикса), `/ru`, `/en`, `/it`
- **Tailwind CSS v4** + собственный набор UI-компонентов в стиле shadcn/ui
- **Prisma 7 + PostgreSQL** (driver adapter `@prisma/adapter-pg`)
- **NextAuth v5 (Credentials)** — вход только в `/admin`
- **Zod** — валидация всех форм и действий
- **Recharts** — графики в админке
- Почта: **свой SMTP-сервер**, или сервис **Resend**, или запись в консоль (dev) — на выбор
- **Telegram Bot API** — уведомления о заказах
- Хранение фото товаров: **локально на сервере сайта** (по умолчанию, без сторонних сервисов), опционально — S3-совместимое облако
- **Vitest** — unit-тесты: промо, статусы заказов, выбор языка и fallback, телефоны, cookie-согласие, hreflang/SEO, доставка, `/llms.txt`

## Что где лежит (для человека без опыта в IT)

Если вы просто владелец сайта и не планируете писать код, вам достаточно
запомнить всего два места:

| Папка/файл | Что там | Нужно ли туда заходить |
| --- | --- | --- |
| **`public/uploads/`** | Здесь физически хранятся **все загруженные фотографии товаров**. Если захотите сделать резервную копию картинок вручную — копируйте эту папку. | Только для бэкапа фото, вручную ничего менять не нужно — фото загружаются через админку сайта |
| **`.env`** | Файл с настройками и паролями сайта: адрес базы данных, данные входа администратора, ключи Telegram и почты. | Да, один раз при первой настройке (раздел ниже) |
| **`theme/`** | **Оформление сайта («темплейт»)**: цвета (`tokens.css`), шрифты (`fonts.ts`), декор — оливковые ветви, золотые рамки, пергаментные плашки (`decor.css`, `decor/`). | Только дизайнеру/разработчику, если нужно перекрасить сайт — см. раздел «Тема сайта» |
| **`messages/`** | Базовые тексты интерфейса на 4 языках (`ro.json`, `ru.json`, `en.json`, `it.json`). | Нет — тексты правятся в админке: **Переводы** |
| **`scripts/aapanel-update.sh`** | Скрипт «всё в одном» для сервера: установка, обновление базы, сборка, права доступа. | Запускается одной командой при установке и каждом обновлении (шаг 6) |
| `.env.example` | Образец файла настроек — «шаблон», с которого вы копируете `.env`. | Нет, только один раз скопировать |
| `app/`, `components/`, `lib/` | Программный код страниц и логики сайта. | **Нет**, трогать не нужно — это работа разработчика |
| `prisma/` | Описание структуры базы данных сайта (какие бывают товары, заказы и т.д.) и демо-данные для первого запуска. | **Нет** |
| `prisma/migrations/` | «История изменений» базы данных — по ним сайт при обновлении понимает, как привести базу в актуальное состояние. | **Нет, никогда не удаляйте эту папку** |
| `node_modules/` | Служебные программные библиотеки — появляется автоматически после установки зависимостей. | **Нет.** Если что-то с сайтом стало не так — эту папку можно спокойно удалить, она соберётся заново |
| `package.json` | Список используемых модулей и команд запуска сайта. | Нет |
| `README.md` | Этот файл с инструкциями. | — |

Короче говоря: **фотографии — в `public/uploads`, пароли и настройки — в
`.env`, всё остальное — программный код, который трогать не нужно.**

# Запуск на своём компьютере (для разработчика)

## 1. Поднимаем PostgreSQL локально

Нужен любой доступный PostgreSQL 14+. Проще всего через Docker:

```bash
docker run --name lastoria-postgres \
  -e POSTGRES_USER=lastoria \
  -e POSTGRES_PASSWORD=lastoria \
  -e POSTGRES_DB=lastoria \
  -p 5432:5432 -d postgres:16
```

Либо локальный PostgreSQL (Ubuntu/Debian):

```bash
sudo service postgresql start
sudo -u postgres psql -c "CREATE USER lastoria WITH PASSWORD 'lastoria' CREATEDB;"
sudo -u postgres psql -c "CREATE DATABASE lastoria OWNER lastoria;"
```

## 2. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения:

```bash
cp .env.example .env
```

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `NEXT_PUBLIC_SITE_URL` | публичный URL сайта (metadata, sitemap, canonical, OG, а также allowedOrigins Server Actions за прокси) |
| `PORT` | порт, на котором слушает `next start` (по умолчанию 3000) |
| `AUTH_SECRET` | секрет NextAuth — любая длинная случайная строка (можно `openssl rand -base64 32`, а можно просто набрать 40+ случайных символов на клавиатуре) |
| `AUTH_URL` | URL приложения для NextAuth |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` / `ADMIN_NAME` | учётные данные администратора, создаваемого сид-скриптом |
| `EMAIL_PROVIDER` | `smtp` (свой почтовый сервер) / `resend` (сервис Resend) / `console` (по умолчанию — письма пишутся в консоль, никуда не уходят) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_SECURE` | настройки, если `EMAIL_PROVIDER=smtp` |
| `RESEND_API_KEY` | ключ, если `EMAIL_PROVIDER=resend` |
| `EMAIL_FROM` | адрес отправителя писем |
| `ADMIN_NOTIFICATION_EMAIL` | адрес администратора для уведомлений о новых заказах |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID` | Telegram-бот для уведомлений (см. ниже) |
| `UPLOAD_PROVIDER` | `local` (по умолчанию и рекомендуется — фото хранятся на самом сервере сайта, никаких сторонних сервисов не нужно) или `s3` (необязательная продвинутая опция) |
| `S3_*` | параметры S3-хранилища, только если `UPLOAD_PROVIDER=s3` |
| `NEXT_PUBLIC_CURRENCY` | код валюты интерфейса (`MDL`) |

## 3. Установка зависимостей, миграции и сиды

```bash
npm install
npm run db:migrate   # prisma migrate dev — создаёт схему в БД
npm run db:seed       # заполняет БД демо-данными
npm run dev            # http://localhost:3000
```

`npm run db:seed` создаёт:
- администратора (`ADMIN_EMAIL` / `ADMIN_PASSWORD` из `.env`);
- 4 категории (Пицца, Напитки, Алкоголь, Снеки);
- 12 демо-товаров с SVG-заглушками фотографий (генерируются на лету, реального
  фотобанка нет — замените на настоящие фото через админку);
- 2 промо (скидка на товар и скидка на категорию);
- 6 демо-заказов в разных статусах и датах (текущий месяц и прошлые), чтобы
  аналитика и дашборд не были пустыми.

Скрипт идемпотентен: повторный запуск не создаёт дубликаты категорий/товаров/
администратора (заказы создаются один раз, если таблица заказов пуста).

> **Dev vs prod миграции.** `npm run db:migrate` (`prisma migrate dev`) — для
> локальной разработки: может интерактивно создавать новые миграции и
> пересоздавать БД при конфликте схемы. На сервере используйте
> `npm run db:deploy` (`prisma migrate deploy`) — он только накатывает уже
> существующие миграции из `prisma/migrations`, ничего не генерирует и не
> спрашивает подтверждений. См. вторую часть README.

## 4. Как создать ещё одного администратора

Через Prisma Studio (`npm run db:studio`) добавьте запись в таблицу `users` с
`passwordHash`, сгенерированным через bcrypt, например:

```bash
node -e "require('bcryptjs').hash('новый-пароль', 10).then(console.log)"
```

и вставьте полученный хэш в поле `passwordHash` новой записи `User`
(`role: ADMIN`).

## 5. Подключение Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен и
   впишите его в `TELEGRAM_BOT_TOKEN`.
2. Напишите боту любое сообщение, затем откройте
   `https://api.telegram.org/bot<TOKEN>/getUpdates` и найдите `chat.id` —
   это `TELEGRAM_ADMIN_CHAT_ID` (либо укажите его в Настройках админки).
3. Без настроенных переменных уведомления в Telegram не отправляются —
   событие логируется и пишется `NotificationLog` со статусом `FAILED` и
   причиной `not configured` (это ожидаемое поведение, не баг).

## 6. Настройка почты: свой сервер, Resend или консоль

`EMAIL_PROVIDER` переключает, как сайт отправляет письма (клиенту — о приёме
заказа, администратору — о новом заказе):

- **`smtp`** — рекомендуется, если у вас уже есть почтовый ящик (например,
  почта вашего хостинга/домена, Яндекс, Mail.ru и т.п.). Заполните
  `SMTP_HOST`, `SMTP_PORT` (обычно `587`), `SMTP_USER`, `SMTP_PASSWORD`,
  `SMTP_SECURE` (`true` только для порта `465`). Никакой сторонний сервис
  для этого не нужен.
- **`resend`** — облачный сервис [Resend](https://resend.com/), нужен
  `RESEND_API_KEY` с сайта resend.com.
- **`console`** (по умолчанию) — письма никуда не отправляются, только
  печатаются в лог сервера. Удобно для проверки без настоящей почты.

## 7. Языки, SEO и проверка hreflang / JSON-LD / llms.txt

**Адреса языков.** Румынский — основной и без префикса (`/menu`), остальные —
с префиксом: `/ru/menu`, `/en/menu`, `/it/menu`. Переключатель языка (в шапке
на компьютере, в меню-«гамбургере» на телефоне) ведёт на ту же страницу на
другом языке и запоминает выбор в cookie `NEXT_LOCALE` на год. Поисковые
роботы cookie не присылают, поэтому всегда видят все 4 версии.

**Если перевода нет**, показывается румынский текст, а если нет и его — первый
заполненный язык (`lib/i18n/translate.ts`). В админке такие места отмечены
жёлтым бейджем «нет перевода».

Проверка в терминале:

```bash
# hreflang (ro, ru, en, it + x-default) и canonical на странице товара
curl -s http://localhost:3000/ru/menu/pizza-margarita | grep -o '<link rel="\(alternate\|canonical\)"[^>]*>'
# og:locale
curl -s http://localhost:3000/it | grep -o 'og:locale[^>]*>'
# JSON-LD (Restaurant, Organization, Menu, Product/Offer, FAQPage, BreadcrumbList)
curl -s http://localhost:3000/delivery | grep -o '"@type":"[A-Za-z]*"' | sort | uniq -c
# карта сайта: все страницы × 4 языка + группы + товары, с xhtml:link hreflang
curl -s http://localhost:3000/sitemap.xml | head -40
curl http://localhost:3000/robots.txt
# справка для AI-ассистентов — собирается автоматически из меню, доставки и настроек
curl http://localhost:3000/llms.txt
```

Или онлайн: [Google Rich Results Test](https://search.google.com/test/rich-results)
(JSON-LD) и любой валидатор hreflang, например
[hreflang Tags Testing Tool](https://technicalseo.com/tools/hreflang/).

Что есть на каждой публичной странице: уникальные `<title>` и description на
её языке, canonical на версию текущего языка, `hreflang` на все 4 версии и
`x-default` (→ румынская), `og:locale` + `og:locale:alternate`. Отзывов и
рейтингов (AggregateRating) в разметке нет намеренно — выдумывать их нельзя.

**«Короткие ответы»** (40–80 слов) на главной и на странице каждого товара —
сжатое описание фактами для людей и AI-поиска. Если в админке поле пустое, текст
собирается автоматически из реальных данных (название, цена, группа, часы,
минимальный заказ). На странице товара в админке есть **SEO-чеклист по
каждому языку**, в Настройках — сводка «сколько товаров без SEO на каком языке».

**`/llms.txt`** заполнять не нужно: файл собирается сам из настроек, меню с
ценами, районов доставки и обновляется после любых правок в админке.

## 8. Тесты

```bash
npm test
```

Покрыты unit-тестами (`tests/`):
- `lib/i18n/*` — порядок fallback языков, выбор перевода по полям, адреса с
  префиксами, одинаковый набор ключей и `{переменных}` во всех 4 словарях;
- `lib/phone.ts` — телефоны `+373…` и `0…` (Молдова и Приднестровье), отказ
  для других стран и неверной длины;
- `lib/consent.ts` — cookie-согласие, аналитика только после «Принять»;
- `lib/delivery.ts` — стоимость доставки района и «бесплатно от суммы»;
- `lib/llms.ts` — автоматический `/llms.txt`;
- промо по типу группы (`PRODUCT_TYPE`), публичные названия промо;
- `lib/pricing.ts` — движок промо `calculateCartPricing` (процент на товар,
  скидка на категорию, конфликт нестекаемых промо, суммирование стекаемых,
  просроченное/будущее/выключенное промо игнорируется, ограничение по
  минимальной сумме заказа, `PRODUCT_OVERRIDE`, неотрицательный итог);
- `lib/constants.ts` — жизненный цикл статусов заказа (`NEXT_ORDER_STATUS`,
  `CONFIRMED_STATUSES`);
- `lib/seo.ts`, `lib/seo-checklist.ts`, `lib/slug.ts` — canonical, hreflang,
  og:locale, JSON-LD, «короткие ответы», SEO-чеклист и транслитерация ЧПУ.

## 8.1. Тема сайта (как «темплейт»)

Всё оформление вынесено в папку `theme/` — чтобы перекрасить сайт или сменить
шрифты, не нужно трогать страницы:

| Файл | Что меняет |
| --- | --- |
| `theme/tokens.css` | Палитра постера: пергамент `#F6EBD8/#F3E4C8`, винный `#7A1F1F`, оливковый `#4E6B3A`, терракота/кирпич `#B85A32/#8C3B22`, уголь `#2B2118`, огонь `#E08A2A…#F2C14E`, карточки `#FFF8EE`, золото `#C7A15A`. Там же — нейтральная тема админки (`[data-theme="admin"]`). |
| `theme/fonts.ts` | Шрифты: Playfair Display (заголовки), Cormorant Garamond курсив (подзаголовки), Source Sans 3 (текст). Все с кириллицей и румынскими буквами. |
| `theme/decor.css` | Текстура бумаги, золотые рамки, пергаментные плашки, клетчатая скатерть, полоса флага Италии. |
| `theme/decor/index.tsx` | SVG-декор: оливковая ветвь, золотой завиток, флажок, заголовок раздела с ветвями, текстовый логотип. |

Компоненты используют только смысловые цвета (`bg-primary`, `text-muted-foreground`,
`border-gold` …), поэтому достаточно поменять значения в `tokens.css`.
**Логотип, favicon и картинка главной** загружаются в админке:
**Настройки → Бренд** (без логотипа показывается текстовый логотип темы,
без картинки — постер `public/brand/poster.jpg`).

## 9. Загрузка файлов

По умолчанию (`UPLOAD_PROVIDER=local`, рекомендуется) изображения хранятся
прямо на сервере сайта, в папке `public/uploads`, и раздаются напрямую
Next.js — **никакие сторонние сервисы не подключаются**. Для бэкапа фото
достаточно скопировать эту папку.

Если понадобится вынести хранение в облако (например, при масштабировании на
несколько серверов), есть необязательная продвинутая опция:
`UPLOAD_PROVIDER=s3` + заполненные `S3_*` — S3-совместимое хранилище (AWS S3,
MinIO, DigitalOcean Spaces и т.п.). Интерфейс `StorageAdapter`
(`lib/uploads/types.ts`) одинаков для обеих реализаций, само приложение не
знает, где физически лежат файлы. Для обычного сайта пиццерии это не нужно.

## 10. Rate-limiting оформления заказа

`lib/rate-limit.ts` — простой in-memory rate-limit (5 заказов за 10 минут на
IP) в рамках **одного инстанса** приложения. Он не переживает рестарт
процесса и не работает согласованно при нескольких инстансах/подах —
для горизонтального масштабирования нужен внешний стор (Redis и т.п.).

# Запуск сайта на сервере через aaPanel

Инструкция для владельца сайта без опыта в программировании. Рассчитана на
**aaPanel 8.0.6**. Названия отдельных пунктов меню могут немного отличаться
в зависимости от языка интерфейса и версии панели — но общая логика та же.

**Принцип инструкции: максимум через кнопки веб-панели, минимум набора
команд.** Набирать команды в терминале придётся лишь один раз — на шаге 6
(подготовка базы данных), потому что панель управления не умеет запускать
разовые команды настройки базы данных через кнопки. Всё остальное — клики
мышкой.

Понадобится: сервер с установленной aaPanel, домен, указывающий A-записью на
сервер.

## Шаг 1. Плагины aaPanel (магазин приложений)

Откройте в левом меню **App Store** (Магазин приложений) и установите (если
ещё не установлены):

1. **Docker Manager** — понадобится, чтобы одной кнопкой запустить базу
   данных PostgreSQL, без ручной установки.
2. **Node.js Version Manager** — у вас он уже установлен (версия 2.3),
   ничего дополнительно делать не нужно.

## Шаг 2. База данных PostgreSQL через Docker Manager

Вместо того чтобы устанавливать PostgreSQL вручную, мы запустим её как
готовую программу в изолированном «контейнере» — Docker Manager делает это
парой кликов.

1. Откройте **Docker Manager → Images** (Образы), в поле поиска введите
   `postgres`, найдите официальный образ `postgres` и нажмите **Pull**
   (Скачать), версию (тег) укажите `16`.
2. Когда образ скачается, откройте **Docker Manager → Containers**
   (Контейнеры) → **Create container** (Создать контейнер) и заполните
   форму:
   - **Image** (Образ): `postgres:16`
   - **Name** (Имя): `lastoria-postgres`
   - **Port** (Порт): слева (на сервере) `5432`, справа (в контейнере)
     `5432` — если панель говорит, что порт `5432` уже занят, впишите слева,
     например, `15432` и запомните это число
   - **Environment** (Переменные окружения) — добавьте три строки:
     - `POSTGRES_USER` = `lastoria`
     - `POSTGRES_PASSWORD` = придумайте сложный пароль и запишите его
     - `POSTGRES_DB` = `lastoria`
   - **Volume** (Том, для сохранения данных при перезапуске) — слева
     (на сервере) укажите новую папку, например
     `/www/dockerdata/lastoria-pgdata`, справа (в контейнере)
     `/var/lib/postgresql/data`
   - **Restart policy** (Политика перезапуска): `always` (всегда)
3. Нажмите **Confirm/Create** и убедитесь, что контейнер запустился (статус
   «Running»/«Работает»).

Запишите себе строку подключения к базе данных (она понадобится в шаге 5):

```
postgresql://lastoria:ВАШ_ПАРОЛЬ@127.0.0.1:5432/lastoria?schema=public
```

(если меняли порт слева на `15432` — замените `5432` после `127.0.0.1` на
`15432`).

> Если в вашей сборке aaPanel есть отдельный плагин **PostgreSQL Manager**
> (в разделе баз данных) — можно использовать его вместо Docker: создайте
> через него пользователя `lastoria` и базу `lastoria`, и точно так же
> соберите строку подключения.

### Шаг 3.1. Права доступа к файлам — обязательно

aaPanel запускает сайт от имени служебного пользователя **`www`**, а файлы,
загруженные и распакованные через File Manager или созданные в Terminal от
`root`, часто получают права «только для root». Тогда сайт не может прочитать
собственные файлы (`node_modules`, `prisma`, `public`, `components` …), сборка
и `db:seed` падают с ошибками доступа, а загрузка фото в админке не работает.

Через File Manager (без консоли):

1. Откройте **File Manager** → `/www/wwwroot/`.
2. Правой кнопкой по папке проекта → **Permission** (Права доступа).
3. Укажите права **755**, владельца (**Owner**) — **www**, и обязательно
   отметьте **Apply to subdirectories** (Применить к подпапкам) → **Confirm**.

То же одной командой в Terminal (если удобнее):

```bash
chown -R www:www /www/wwwroot/lastoria && chmod -R u+rwX,go+rX,go-w /www/wwwroot/lastoria
```

> Не пугайтесь: скрипт из шага 6 делает это сам в конце каждого запуска. Но
> если вы запускаете отдельные команды (`npm install`, `npm run build`) от
> `root`, новые файлы снова станут «чужими» для `www` — просто повторите этот
> шаг или запустите скрипт из шага 6.

*(Если вы разработчик и предпочитаете Git — можно вместо этого открыть
Terminal и выполнить `cd /www/wwwroot && git clone <URL> lastoria`.)*

## Шаг 4. Настройка `.env` через файловый менеджер

Файл `.env` — это «записная книжка» сайта с паролями и настройками. Редактируем
его прямо в браузере, без консоли:

1. В **File Manager** зайдите в `/www/wwwroot/lastoria`.
2. Найдите файл `.env.example`, нажмите на него правой кнопкой →
   **Copy** (Копировать), затем **Paste** (Вставить) в этой же папке —
   появится копия, например `.env.example copy`.
3. Переименуйте копию в `.env` (обязательно с точкой в начале, без
   расширения `.txt`).
4. Дважды кликните на `.env` — откроется встроенный текстовый редактор.
   Заполните (остальные строки можно на первое время оставить как есть):

   | Строка | Что вписать |
   | --- | --- |
   | `DATABASE_URL` | строка подключения из шага 2 |
   | `NEXT_PUBLIC_SITE_URL` | `https://ваш-домен` |
   | `AUTH_URL` | `https://ваш-домен` |
   | `AUTH_SECRET` | любая длинная случайная строка — просто наберите на клавиатуре 40+ произвольных букв, цифр и символов подряд |
   | `PORT` | `3000` (запомните — это же число укажете в шаге 5) |
   | `ADMIN_EMAIL` | email, под которым будете входить в админку |
   | `ADMIN_PASSWORD` | пароль для входа в админку |

   Если хотите сразу настроить уведомления — заполните также блок
   `TELEGRAM_*` (см. п. 5 первой части README) и блок почты `EMAIL_PROVIDER`
   / `SMTP_*` (см. п. 6 первой части README).
5. Нажмите **Save** (Сохранить) в редакторе.

## Шаг 5. Node.js-проект: установка и запуск — без консоли

Здесь мы говорим панели, как запускать сайт, через готовую форму.

1. В левом меню откройте **Website** (Сайты) → вкладку **Node project**
   (Node-проект) → **Add Node project** (Добавить Node-проект).
2. Заполните форму:
   - **Project path** (Путь проекта): `/www/wwwroot/lastoria`
   - **Run directory** (Рабочая директория): та же папка, что и путь проекта
   - **Startup file** (Файл запуска): впишите слово `npm` — это специальное
     значение, aaPanel поймёт его как команду `npm run start`, которая уже
     настроена в проекте
   - **Port** (Порт): `3000` (или то число, что вы указали в `.env`)
   - **Node version** (Версия Node.js): выберите `22.x` из списка
     установленных версий
3. Нажмите **Confirm/Submit** (Подтвердить) — проект появится в списке.
4. Кликните на имя проекта в списке, чтобы открыть его карточку. Внутри
   найдите вкладку **Module** (Модули/Зависимости) и нажмите кнопку
   **One-key install** (Установить одной кнопкой) — панель сама установит
   все нужные программные библиотеки (это то же самое, что команда
   `npm install`, но без консоли).
5. Дождитесь надписи об успешной установке.

> Если кнопка «One-key install»/«Установить» не появляется или зависает —
> зайдите в File Manager, удалите (если она уже создалась) папку
> `node_modules` внутри `/www/wwwroot/lastoria` и повторите шаг 4.

## Шаг 6. Подготовка базы данных — единственный шаг с консолью

Панель управления не умеет запускать разовые команды настройки базы данных
через кнопки, поэтому этот (и только этот) шаг делаем через встроенный
**Terminal** (Терминал, пункт в левом меню aaPanel). Сначала убедитесь, что
файл `.env` заполнен (шаг 4).

Все серверные действия собраны в один скрипт — запускаете одну команду, он
делает остальное сам:

```bash
bash /www/wwwroot/lastoria/scripts/aapanel-update.sh
```

Что он делает по шагам (на экране видно, какой шаг идёт):

1. находит `npm`, который поставил плагин *Node.js Version Manager* (он лежит
   в отдельной папке, поэтому в обычном терминале команда `npm` «не найдена» —
   скрипт это обходит сам);
2. устанавливает библиотеки (`npm install`);
3. создаёт «переводчик» между кодом сайта и базой данных (`prisma generate`) —
   **без этого шага после обновления кода появляется ошибка вида
   `The column settings.deliveryZones does not exist`**;
4. создаёт/обновляет таблицы в базе (`prisma migrate deploy` — ничего не
   удаляет, данные сохраняются);
5. заполняет демо-товары и недостающие переводы (`seed`; ничего, что вы
   правили в админке, не перезаписывает). Если нужен пустой каталог —
   запустите скрипт с `--no-seed` в конце команды;
6. собирает сайт (`next build`, 1–3 минуты);
7. выставляет права: владелец всех файлов — `www`, папки 755, файлы 644,
   `.env` — 600 (читает только владелец).

В конце должно появиться зелёное **«Готово!»**. Если вместо этого красная
надпись **«ОШИБКА: …»** — в ней написано, чего не хватает (нет `.env`, не
найден Node.js и т.п.).

Строка `npm warn config init.module Use --init-module instead` в выводе —
безобидное предупреждение самого npm, на работу сайта не влияет.

<details>
<summary>То же самое вручную, по отдельным командам</summary>

```bash
export PATH=$PATH:$(ls -d /www/server/nodejs/v*/bin | sort -V | tail -n 1)
cd /www/wwwroot/lastoria
npm install
npm run db:deploy        # таблицы + prisma generate
npm run db:seed          # необязательно: демо-данные (сам делает prisma generate)
npm run build            # сборка (сама делает prisma generate)
chown -R www:www /www/wwwroot/lastoria && chmod -R u+rwX,go+rX,go-w /www/wwwroot/lastoria
```

Если не найден `npm`, посмотрите в File Manager точное имя папки в
`/www/server/nodejs/` (например, `v22.20.0`) и используйте полный путь:
`/www/server/nodejs/v22.20.0/bin/npm run db:deploy`.

</details>

## Шаг 8. Домен и SSL-сертификат

1. В карточке Node-проекта найдите раздел про домен (обычно называется
   **Domain** / **Add domain** — «Домен» / «Добавить домен») и впишите ваш
   домен, например `lastoria.md`. Панель сама создаст сайт и настроит показ
   через него (обратный прокси на порт из шага 5) — редактировать конфиг
   Nginx вручную не требуется.
2. В той же карточке найдите раздел **SSL** и выпустите бесплатный
   сертификат **Let's Encrypt** (обычно достаточно нажать «Apply»/«Применить»
   и дождаться готовности), затем включите принудительный переход на HTTPS.

Если после этого страница входа в админку показывает ошибку, связанную с
доменом или CSRF/Server Actions — откройте настройки домена/reverse proxy в
карточке проекта и убедитесь, что среди заголовков передаётся
`X-Forwarded-Host` со значением вашего домена (это не всегда нужно — в
`next.config.ts` уже заложена подстраховка на основе `NEXT_PUBLIC_SITE_URL`,
но для некоторых версий панели может понадобиться донастройка).

## Шаг 10. Если не сохраняются фото или сайт не видит свои файлы

Почти всегда причина — права доступа: файлы принадлежат `root`, а сайт
работает от пользователя `www`. Повторите **шаг 3.1** (или просто запустите
скрипт из шага 6 — он выставляет права в конце) и нажмите **Restart**.

## Обновление уже работающего сайта до мультиязычной версии

Если сайт уже был запущен по этой инструкции раньше (версия только на русском):

1. Сделайте резервную копию базы: **Databases** (или Docker → контейнер
   PostgreSQL) → **Backup**. На всякий случай.
2. Загрузите новую версию кода (шаг 3) поверх старой. Файл `.env` и папку
   `public/uploads` (загруженные фото) не удаляйте.
3. В Terminal:
   ```bash
   bash /www/wwwroot/lastoria/scripts/aapanel-update.sh
   ```
   Скрипт (см. шаг 6) переносит данные в новую структуру: существующие товары,
   группы, промо и заказы **сохраняются**, их русские названия становятся
   русским переводом, а seed дописывает недостающие переводы на румынский,
   английский и итальянский для стартовых товаров и создаёт Кишинёв с
   районами — ничего из того, что вы уже правили в админке, он не перезаписывает.
4. Нажмите **Restart**.
5. Откройте админку → **Доставка** и **укажите реальные цены по районам**
   (в демо-данных стоят условные 50 MDL). Старые зоны доставки перенесены в
   Кишинёв скрытыми — удалите или включите их.
6. Админка → **Переводы**: просмотрите товары и тексты без перевода.

## Обновление сайта после изменений в коде

1. Замените изменённые файлы через File Manager (или повторите шаги 3 для
   новой версии архива).
2. В Terminal — одна команда (установит библиотеки, обновит базу, соберёт
   сайт и выставит права):
   ```bash
   bash /www/wwwroot/lastoria/scripts/aapanel-update.sh --no-seed
   ```
3. Нажмите **Restart** в карточке Node-проекта.
