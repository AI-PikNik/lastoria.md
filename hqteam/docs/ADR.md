# Architecture Decision Records

## ADR-001. Подпроект `hqteam/` внутри репозитория lastoria.md
**Контекст.** В репозитории уже есть Next.js-приложение магазина; ТЗ задаёт отдельную структуру `hqteam/`.
**Решение.** Изолированный Python-подпроект в `hqteam/` со своими зависимостями, тестами и Docker. Код
Next.js не затрагивается.
**Последствия.** Подпроект можно вынести в отдельный репозиторий без изменений (`git subtree split`).

## ADR-002. Стек по умолчанию
Python 3.11, FastAPI, SQLAlchemy 2, Pydantic v2, Alembic, Typer, pytest/ruff/mypy, Anthropic SDK. SQLite
для dev, PostgreSQL для prod: в моделях только переносимые типы, миграция проверена рендером SQL для
PostgreSQL. Для savepoint'ов в SQLite отключено собственное управление транзакциями pysqlite.

## ADR-003. Детерминированное ядро + LLM для текста
**Решение.** Расчёты, статусы, ссылки на источники и маршрутизацию делает код и инструменты; LLM — только
пояснения. **Почему:** приёмка требует воспроизводимых сценариев, запрета на выдумывание и проверяемости.
**Режимы:** `HQ_LLM_MODE=offline` (по умолчанию, без сети) и `live` (Anthropic Messages API, модель
`claude-opus-5-5`, effort `medium`, server-side fallbacks).

## ADR-004. Очередь — DB-backed worker, Celery опционально
Таблица `tasks` и есть очередь; `scheduler.run_until_idle` — однопоточный воркер. Для горизонтального
масштабирования — Celery + Redis с `SELECT … FOR UPDATE SKIP LOCKED` на PostgreSQL. Сейчас это не
требуется: нагрузка — десятки задач на проект.

## ADR-005. RAG без внешнего векторного сервиса
BM25 по `knowledge_chunks` в той же БД. Каждый фрагмент несёт источник, URL, дату загрузки, юрисдикцию,
версию. Для юридических и налоговых тем семантическая близость менее важна, чем точная норма и свежесть,
а BM25 даёт объяснимое ранжирование. ChromaDB/Qdrant подключаются как альтернативный backend поиска
(extra `vector`); интерфейс `search()` при этом не меняется.

## ADR-006. Право и налоги: только из загруженного официального текста
- В коде и seed нет текстов законов. `knowledge_base/legal/sources.json` — реестр того, что и где
  проверять; точный URL акта заполняет юрист. Пустой URL → загрузка отказывает, чтобы главная страница
  портала не попала в индекс как «закон».
- Загрузка — только с хостов allowlist (`HQ_LEGAL_FETCH_ALLOWED_HOSTS`), с датой проверки и checksum.
- Вывод выдаётся только при официальном, проверенном, свежем (≤90 дней) источнике нужной юрисдикции; иначе
  `NEEDS_VERIFICATION` и вопрос LEGAL_HUMAN / FIN_HUMAN.
- Ставка НДС применяется только если есть источник **и** факт подтверждён FIN-HUMAN в
  `knowledge_base/fin/tax_facts.json` со ссылкой на checksum документа.
- Закон РМ о ПДн: по вторичным источникам (проверено 2026-10-28) Закон №133/2011 заменён Законом
  №195/2024 с 23.08.2026. В реестре это помечено как требующее подтверждения по официальному тексту.

## ADR-007. Тип сообщения NOTIFY
К пяти типам из ТЗ добавлен `NOTIFY`: уведомление PM о прямой передаче (режим B). Без отдельного типа PM
пришлось бы слать REQUEST, который ничего не требует, и смысл журнала исказился бы.

## ADR-008. Одобрения: привязка к содержимому и идемпотентность
- `payload_hash = sha256(action, entity, payload)`. При изменении содержимого старое одобрение
  недействительно.
- В payload фиксируются checksum'ы артефактов. Если после одобрения появилась новая версия КП или акта,
  исполнение отказывает.
- `external_operations.idempotency_key UNIQUE`: повторный execute возвращает прежний результат.
- Решает только принципал `kind=human` с ролью из `APPROVAL_ACTIONS`. ADMIN не одобряет за другие роли
  (разделение обязанностей).
- `HQ_EXTERNAL_SEND_MODE=simulate`: отправка пишет JSON в `outbox/`. Live-провайдеры не подключены
  намеренно.

## ADR-009. Уровень 3 не реализуется вовсе
Для запрещённых действий (`apply_prod_config`, `delete_data`, `grant_access`, `sign_e_signature`,
`payment_transaction`…) нет исполняющего кода; `check_action` всегда отказывает. Конфиги ARCH сохраняются
как артефакты с `meta.apply = REVIEW_ONLY`.

## ADR-010. Демонстрационный rate card
Ставок HQTeam нет, поэтому смета считается по `rate_card.example.json` с флагом `is_placeholder`. Он
выводится в каждой смете и КП. При `HQ_ENV=prod` расчёт по нему запрещён. Цены лицензий/оборудования не
оцениваются: `NEEDS_VENDOR_QUOTE`.

## ADR-011. Сценарий 2: первая итерация стенда намеренно минимальна
`arch.scaffold` rev1 не содержит идемпотентности синхронизации и теста восстановления. SUPPORT находит это
статической проверкой, ARCH выпускает rev2. Так цикл исправлений SUPPORT → ARCH воспроизводится
детерминированно. Проверки, требующие запуска стенда (нагрузка, реальный restore, обмен с учётной
системой), имеют статус `NOT_VERIFIED` и не считаются пройденными.
